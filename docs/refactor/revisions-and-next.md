# 修訂紀錄與後續清單

## 修訂理由

| 原始問題 | 本次修訂 | 理由／影響 |
|---|---|---|
| 工作區與/Final_proj位置不同 | 使用實際上一層Git repo，建立附件hash | 防止建立空替代專案或誤認DietSense |
| 緒論採A–F提綱 | G–L邏輯的七段連貫文章 | 直接回答重要性、問題、限制與可驗證貢獻 |
| 摘要無可核字數或英文 | A–F、299字（含標點去空白）、英Title/Abstract/Index Terms | 語氣忠於無實驗階段 |
| AI研究截至原選文 | 回查原文並加入A6（2026） | 承認直接近似研究，收窄創新主張 |
| 5/3/10答題不足 | 每模式含條件，每爭點含代價，每問含推理與影響 | 支援口試；不把功能清單當思維 |
| 原爭點「快篩或節能驗證」易成假二分 | 改DQ3為自適應調查與固定完整流程 | 有直接近似證據且可用三組實驗驗證；原來源保留 |
| 工具與LLM預算語意未完整分開 | 工具10、LLM5；模板本地；保存失敗明示 | 規劃與報告失敗可閉合，不無限重試 |
| flowchart未明畫品質工具／規則失敗 | 補兩分支，報告失敗包含模板 | 圖、正文、偽碼與spec一致 |
| 多份技術內容可漂移 | DESIGN與新evaluation作編輯源；生成區塊有驗證 | 不維護兩份不同技術真相 |
| 無OpenSpec、scenario或任務追蹤 | CLI init、1主spec＋5delta spec、依賴tasks | 既有文件能力與未來產品嚴格分流 |
| 原文件build直接覆寫期中輸出 | 新build_refactor只寫refactor目錄 | 保留原稿與原簡報，提交可同時比對 |
| 指標有分母但成功判準與消融不足 | 新增成對RQ判準、驗證器及規則消融、誤拒率 | 防止靠空報告或全部拒絕取得高分 |
| A2Z資訊圖部分字母重新定義 | 依原PDF保留PA–PM、Q–V及W–Z | 避免複製AI解析錯誤；結果欄維持規劃 |

## 非阻斷的待補資訊

- 真正BDG2建築、12週日期及檔案commit/hash；後續按排序／品質規則選，不能依結果挑樣本。
- 實際LLM供應商／版本／費用與API可用性；本次沒有索取或寫入金鑰。
- 兩名審閱者、分工與課程截止日；四週僅是開發估計。
- 設施人員需求訪談；現況只設定校園／辦公管理情境。
- 現場排程、設備狀態、維修／介入真值；沒有這些不升級為確診或節能研究。
- A5/A6正式出版資訊可再補，但現有arXiv引用已可追溯，無需補造DOI。
