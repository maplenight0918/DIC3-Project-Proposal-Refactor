# A2Z原定義對應表

來源為附件《A2Z outline example.pdf》，頁首「2020 A-Z SOP」，已核對實際頁面。下列保留原英文標籤與中文定義，排版空格正規化；原圖不是規範實驗必須已完成的命令。尤其Q不是Deep Questions、Y不是安全性，資訊圖的改寫不採用。原文以「V. Conclusion」作章節編號，與實驗項字母V不同。

| 字母 | 原始A2Z定義 | 本提案對應與狀態 |
|---|---|---|
| A | Attention Getter Motivation 動機及引題 | §1.1 A；D1客觀動機 |
| B | But (However 挑戰) | §1.1 B；總表與證據限制 |
| C | Cure 解藥 (we propose a novel scheme to address the challenges) | §1.1 C；提出系統但不宣稱演算法首創 |
| D | Development (我們的方法設計 based on …) | §1.1 D；工具/分析/領域分工 |
| E | Experiments (To evaluate our proposed scheme, we conduct experiments on …) | §1.1 E；改為will evaluate，尚未實驗 |
| F | Findings (results show that…) | §1.1 F；Expected Outcomes，不套用已完成時態 |
| G | General 現況 | §2第1–2段 |
| H | However (挑戰, same as B… but longer …) | §2第2、4段 |
| I | In literature (文獻中有關此問題的解, 大分類 from old to new, simple to complex) | §2第3段 |
| J | Judgement (評論各類方法優缺點, SWOT) | §2第4段；§3比較限制 |
| K | Keypoint (設計精神與novelty, 再次強調major goals Contribution summary) | §2第5–6段，三層價值 |
| L | List the organization (文章結構交代) | §2末句 |
| M | Methods (文獻中有關此問題的解, 分類 from old to new, simple to complex) | §3.1–3.2分類比較 |
| N | New proposed (new trend, new novelty of the proposed scheme) | §3.4情境驗證缺口；不以Agent為創新 |
| O | Organize (based on Judgement評論各類方法優缺點, SWOT列表4x5table歸納) | §3.3採正式作業指定8欄Article Summary Table；另有ADR取捨，非照抄4×5 |
| P | Proposed Scheme (From PA to PM) | §5整體方案 |
| PA | Aim = Statement 目標 | §5 Problem/Requirements |
| PB | Basedon / bkground / Be focus on / Benefit | §5 BDG2、領域背景與使用情境 |
| PC | Cure / Cause / 解法及有用的原因 | §5工具計算與證據約束 |
| PD | Design 架構 (paper的設計是結合…怎樣典範轉移成為這篇重點) | §5 Architecture；不宣稱典範轉移已被證明 |
| PE | Paper element (有哪些element) | §5 Components八模組 |
| PF | Formulation / Foundation 功能 | §5 Algorithm；殘差、分位數與事件 |
| PG | Graph (架構圖說明) | §5兩圖、assets/refactor/ |
| PH | How (How they achieve the design goal) | §5介面、前提及降級 |
| PI | Implementation / Interaction among elements / flow chart or Pseudo code | §5流程、44行偽碼、未實作mapping |
| PJ | Jump to an example | §5 illustrative_only的240 kWh例；非結果 |
| PK | Key points contribution | §7三層預期產出 |
| PL | Later how to do simulation | §6固定資料與注入規劃 |
| PM | Math proof | 不適用正式定理證明；§5量綱與時間隔離不變量是設計檢查，不能改名成已完成math proof |
| Q | Quality and Quantity (實驗量與性質指標, performance metrics) | §6指標分母與必要資訊 |
| R | Related method to compare (比較那些演算法) | §6 B0/B1、三組與消融 |
| S | Simulation Setup | §6資料選樣、8/2/2週與seed |
| T | Tuning what parameters in simulations | §6校準程序、固定q與品質門檻；不在test調參 |
| U | Useful results | 尚未完成；§7預期產出、§6結果表待測 |
| V | Verify the effectiveness of our proposed scheme | 尚未完成實驗；§6驗證協議，文件validate不能替代 |
| W | What proposed (回顧研究意義動機研究挑戰) | §7回顧研究範圍 |
| X | eXcel (專精哪種情境, 演算法優點這篇文章解決的問題提出的Solution及方法) | §7有限總表情境；優點為待驗證設計價值 |
| Y | Yields (產出, results show….實驗數據與模擬與結果簡述) | 只有文件與規格完成；實驗產出待測，不用期末交付清單替代結果定義 |
| Z | Zen (結論與future work最後強調問題獲得怎樣的解決與結論觀察與研究貢獻) | §7限制及後續，未推論已解決研究假設 |
